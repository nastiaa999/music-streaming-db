## Аналитические запросы

В директории `sql/queries` представлены семь сложных аналитических запросов, моделирующих реальные сценарии работы музыкального стримингового сервиса. Запросы решают задачи формирования рекомендаций, сегментации аудитории и анализа контента.

| Файл | Бизнес-задача | Ключевые SQL-механизмы |
|------|---------------|------------------------|
| `01_top_5_tracks.sql` | Формирование актуальных чартов: топ-5 треков по каждому жанру за последние 30 дней. | CTE, `ROW_NUMBER() OVER(PARTITION BY)` |
| `02_recommend_public_playlists.sql` | Персональные рекомендации. Учитывает профиль пользователя, коэффициент разнообразия вкусов (`diversity_factor`) и популярность треков среди ровесников. | Множественные CTE, кастомный скоринг, `COALESCE`, `CASE` |
| `03_collaborations.sql` | Анализ коллабораций: поиск топ-10 пар исполнителей с наибольшим числом совместных треков. | Самосоединение (self-join) с условием `<`, `DENSE_RANK()` |
| `04_rfm_segmentation.sql` | RFM-сегментация аудитории. Разделение пользователей на `Champions`, `Regular` и `Churned` на основе активности. | `NTILE(4)`, агрегация, классификация через `CASE` |
| `05_inactive_songs.sql` | Поиск «мёртвых» треков в активных плейлистах (не прослушивались за последние 90 дней) для оптимизации контента. | `NOT EXISTS` (anti-join), `ARRAY_AGG() OVER()` |
| `06_albums_listening_dynamics.sql` | Оценка популярности альбомов после релиза: накопительное количество прослушиваний и скользящее среднее за 7 дней. | `SUM() OVER(ROWS UNBOUNDED PRECEDING)`, `AVG() OVER(ROWS BETWEEN)` |
| `07_users_genre_preferences.sql` | Анализ меломанов: поиск пользователей с широким вкусом (5+ жанров), определение их основного жанра и списка альтернативных интересов. | `COUNT(*) OVER()`, `RANK()`, `ARRAY_AGG(...) FILTER(WHERE ...)` |

Все запросы оптимизированы с помощью индексов (см. `sql/indexes.sql`).
